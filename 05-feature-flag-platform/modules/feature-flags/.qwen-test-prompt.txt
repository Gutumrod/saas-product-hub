```ts
createFeatureFlagClient(config?: FeatureFlagConfig): FeatureFlagClient

type FeatureFlagQuery = { key: string; context?: FeatureFlagContext; defaultValue?: boolean };

type FeatureFlagResult = { key: string; enabled: boolean; source: 'store'|'default_fallback'|'error_fallback'; reason: string };

interface FeatureFlagStore { getFlag(key: string, context?: FeatureFlagContext): Promise<StoredFlag | null>; }

type FeatureFlagConfig = { store?: FeatureFlagStore; defaultFallback?: boolean; hooks?: FeatureFlagLoggingHooks };
type FeatureFlagLoggingHooks = { onEvaluation?: (info: SanitizedFlagEvaluationInfo) => void; onError?: (error: FeatureFlagError, query: FeatureFlagQuery) => void };
type FeatureFlagErrorCode = 'FLAG_KEY_INVALID' | 'FLAG_PROVIDER_ERROR' | 'FLAG_VALUE_INVALID';
```

## Evaluation semantics (ground truth)

1. Invalid key (empty/non-string) -> FLAG_KEY_INVALID -> onError hook -> result { source:'error_fallback', reason:'Invalid flag key' }.
2. Store returns null (missing) -> { source:'default_fallback', reason:'Flag not found in store' }.
3. Store throws -> wrapped FLAG_PROVIDER_ERROR -> onError hook -> { source:'error_fallback', reason:'Provider error: storage lookup failed' }.
4. Stored flag with non-boolean enabled or malformed structure -> FLAG_VALUE_INVALID -> onError hook -> { source:'error_fallback', reason:'Invalid flag value' }.
5. Valid stored flag: find first matching targeting rule (exact match on tenantId/userId/environment, AND semantics, omitted fields are wildcards). If matched -> enabled = rule.enabled, source:'store', reason:'Matched targeting rule'. Else -> enabled = storedFlag.enabled, source:'store', reason:'Evaluated flag default state'.
6. Fallback value precedence: query.defaultValue (if boolean) -> config.defaultFallback (if boolean) -> false.
7. onEvaluation hook fires in finally on every completed path (including fallbacks/errors). onError fires on invalid key, provider error, invalid value.
8. Hook exceptions are swallowed and never affect the result.
9. isEnabled() routes through getFlag() and returns result.enabled.
10. No caching: store.setFlag() updates are immediately visible on the next query.
11. Independent contexts: parallel queries with different tenant/user contexts evaluate independently.
