เพิ่ม Product ใหม่ในอนาคต

เป้าหมายคือ “เพิ่ม Profile” ไม่ใช่ “สร้างระบบจ่ายเงินใหม่”

1สร้าง Billing Profile

กำหนด subscription / one-time, currency, plans และ lifecycle

2ผูก Stripe mapping

กำหนด Stripe Product / Price สำหรับ profile version นั้น

3ต่อ Entitlement Adapter

บอกว่าจะเปิด/ลด/ยกเลิกสิทธิ์ใน Product อย่างไร

4ผ่าน Test Fixture

ลอง checkout, webhook, reconcile และ failure cases ใน Test Mode

5ผ่าน Isolation Test

พิสูจน์ว่า Product A ไม่มีทางไปเปลี่ยนสิทธิ์ Product B

6ค่อย Activate

เมื่อ admission gate ครบจึงเปิดใช้ profile version นั้น

ของที่ “ห้ามมั่ว” เด็ดขาด

ห้ามมี global current_profile
ทุก request / event / job ต้องรู้ Product ของตัวเอง ห้ามสลับ profile จากตัวแปรกลาง
Product ห้ามเลือก Stripe Price ID
Product ขอ “plan” ได้ แต่ Price จริงต้อง resolve ฝั่ง Billing Core จาก profile
Metadata ไม่ใช่หลักฐานเรื่องเงิน
ใช้ช่วย route ได้ แต่เงินจริงและ entitlement ต้องยืนยันจาก provider truth + reconciliation
