## Contract compliance, verified directly in the code

| Requirement | Verified |
|---|---|
| `GET /v1/billing/control/snapshot` only | `method: "GET"` is the sole method in the file; the header comment forbids adding a mutation method |
| Account-scoped addressing: product + environment + explicit `accountId` | enforced; a missing `productCode`/`accountId` is refused as `invalid_request` **before any network call** |
| **No product-wide enumeration** | no `accounts[]`/`listAll`/enumerate path exists; the shape is not representable |
| `control_read` scope + bound account assertion | token plus HMAC-SHA256 assertion bound to product, environment, account, `operation_id`, action |
| SB01 stays `productId` native; Control resolves `productCode -> productId` | credentials are keyed by SB01-native `productId`; resolution happens Control-side |
| `providerStatus` mapping with unknown values rejected | explicit reject for `unpaid`, `incomplete`, `incomplete_expired`, `paused`, empty and unrecognised — never coerced |
| Failure modes distinguishable and fail-closed **visibly** | `connection_failed`, `timeout`, `http_error` (retryable only on 503), `malformed_response`, `contract_violation`, `invalid_request` — each rejects the read and moves readiness to `degraded` with `canRead: false`; a later success recovers to `ready` from last-known state |
| Rejection is never repair | `validateSnapshot` is unchanged and still applies as a second layer; demo data is never substituted |
| `canExecutePaymentActions: false` | literal `false` at every site: the contract type, and the unconfigured/ready/degraded readiness paths |
| No provider SDK / mutation / entitlement write / local billing truth | none present; the transport is GET-only and the boundary is enforced in the header comment and by test |
| Secret hygiene | secrets appear only in the signed assertion header; never in a URL, error message, readiness reason or log line. Error messages are fixed strings |
| Absent/malformed config stays fail-closed | the parser returns `null` on a missing/invalid base URL, unparseable JSON, or any entry missing a required field, and `getBillingCoreAdapter()` then returns `UnconfiguredBillingCoreAdapter` — never a demo fallback |
