=== SOURCE OF TRUTH (feature-flags brief) ===
Objective: a central contract for runtime on/off feature toggling without binding business logic to storage/provider.

Architecture:
```
Business Logic
      ↓
Feature Flag Core
      ↓
Flag Store / Provider
```

IMPORTANT BOUNDARY: Feature Flag is NOT Subscription Entitlement. Feature flags are for rollout, kill switch, pilot feature, temporary enable/disable, internal test, runtime control. Entitlement is whether a user/tenant may use a feature per plan. NEVER use feature flags as permission/billing entitlement.

Public API (v0.1 boolean flags only): isEnabled(), getFlag().

FeatureFlagContext:
```ts
type FeatureFlagContext = {
  tenantId?: string
  userId?: string
  environment?: string
  attributes?: Record<string, string | number | boolean>
}
```

Call:
```ts
isEnabled({ key, context, defaultValue })
```

Result:
```ts
type FeatureFlagResult = {
  key: string
  enabled: boolean
  source?: string
  reason?: string
}
```
`reason` MUST NOT expose internal secrets/query details.

Store Contract:
```ts
interface FeatureFlagStore {
  getFlag(key, context): Promise<StoredFlag | null>
}
```
Core does NOT know the storage (memory / Postgres / Supabase / remote flag service / config service).

v0.1 Adapter: implement Memory Adapter only, for tests, local development, contract validation. The Memory Adapter MUST declare clearly: it is NOT a distributed production flag store. Production adapter waits for a real project pilot.

Default Behavior: every flag query must have a deterministic fallback (flag missing, provider unavailable). Safe default: use explicitly supplied defaultValue; if none, false.

Targeting: v0.1 no experimentation engine. Simple exact matching on tenantId/userId/environment allowed. Memory Adapter need not implement a complex rule language.

Runtime Updates: core must not cache without invalidation. v0.1 no cache needed.

Error Contract: FLAG_KEY_INVALID, FLAG_PROVIDER_ERROR, FLAG_VALUE_INVALID. Provider failure must not crash the app if a fallback policy exists, but must expose diagnostics via result/hook appropriately.

Security: never put API secrets/password/access tokens/private credentials in flag values. Feature flag is NOT secret storage. Sensitive server-side flags must not expose full flag definitions to client by default.

Out of Scope: A/B test analytics, conversion tracking, experiment statistics, billing entitlement, permission engine, remote admin dashboard, secret management, complex segmentation language, percentage rollout v0.1, multivariate flags v0.1.

Tests (per brief): flag true, flag false, missing flag, default true, default false, tenant context, user context, environment context, provider failure, invalid value, memory update visible at runtime, independent contexts.

Definition of Done: Boolean Feature Flag contract, FeatureFlagContext, Store interface, Memory adapter, Deterministic fallback, Runtime mutable behavior proven, No entitlement duplication, No secret storage, Tests, Integration example, MODULE.md, VERSION.
